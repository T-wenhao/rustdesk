# Custom RustDesk Configuration System

This document describes the custom configuration system that allows building RustDesk with pre-configured server settings.

## Overview

The custom configuration system enables you to build RustDesk with embedded server configuration (client key, API server, relay server, and rendezvous server) that gets applied at runtime. This is useful for:

- **CI/CD pipelines**: Automatically build custom clients for different environments
- **White-label deployments**: Create branded versions with your own servers
- **Enterprise deployments**: Distribute pre-configured clients to users

## Configuration Parameters

| Environment Variable | Description | Required | Example |
|---------------------|-------------|----------|---------|
| `CUSTOM_CLIENT_KEY` | Client authentication key | No | `my-client-key-123` |
| `CUSTOM_API_SERVER` | API server URL (with protocol) | No | `https://api.example.com` |
| `CUSTOM_RELAY_SERVER` | Relay server URL (with protocol) | No | `https://relay.example.com` |
| `CUSTOM_RENDEZVOUS_SERVER` | Rendezvous server hostname | **Yes** | `example.com` |

## Usage Methods

### Method 1: Environment Variables + Cargo Build

```bash
export CUSTOM_RENDEZVOUS_SERVER="your-server.com"
export CUSTOM_CLIENT_KEY="your-key"
export CUSTOM_API_SERVER="https://api.your-server.com"
export CUSTOM_RELAY_SERVER="https://relay.your-server.com"

cargo build --release --features flutter
```

### Method 2: Using the Build Script

```bash
# Using command line arguments
./build_custom.sh --key "your-key" --rendezvous "your-server.com"

# Using environment file
./build_custom.sh --env-file .env.custom

# Using environment variables
CUSTOM_CLIENT_KEY="your-key" CUSTOM_RENDEZVOUS_SERVER="your-server.com" ./build_custom.sh
```

### Method 3: Python Script Directly

```bash
python3 build_custom_config.py \
  --output src/custom_config.rs \
  --rendezvous-server "your-server.com" \
  --key "your-key" \
  --api-server "https://api.your-server.com" \
  --relay-server "https://relay.your-server.com"
```

### Method 4: GitHub Actions CI

See `.github/workflows/build-custom.yml` for the complete CI workflow.

```yaml
- name: Build Custom Client
  env:
    CUSTOM_CLIENT_KEY: ${{ secrets.CLIENT_KEY }}
    CUSTOM_RENDEZVOUS_SERVER: ${{ secrets.RENDEZVOUS_SERVER }}
    CUSTOM_API_SERVER: ${{ secrets.API_SERVER }}
    CUSTOM_RELAY_SERVER: ${{ secrets.RELAY_SERVER }}
  run: cargo build --release --features flutter
```

## How It Works

### Build Time

1. **build.rs** reads environment variables
2. **generate_custom_config()** creates `src/custom_config.rs` with static configuration
3. Cargo compiles the generated configuration into the binary

### Runtime

1. Application starts
2. `apply_build_config()` is called early in initialization
3. Build-time configuration is applied to the config system
4. Settings take effect immediately

### Integration Points

The custom configuration is applied in these locations:

- **Desktop app**: `src/core_main.rs` - `core_main()`
- **CLI**: `src/main.rs` - `main()` with `cli` feature
- **Flutter**: `src/main.rs` - `main()` with `flutter` feature
- **Flutter FFI**: `src/flutter_ffi.rs` - `initialize()`

## Generated File Example

When built with environment variables, `src/custom_config.rs` looks like:

```rust
//! Custom Server Configuration (Generated)
//!
//! This file is automatically generated during build.
//! DO NOT EDIT MANUALLY - changes will be overwritten.

use hbb_common::config::Config;
use hbb_common::log;

/// Build-time injected configuration
pub struct BuildConfig {
    pub key: &'static str,
    pub api_server: &'static str,
    pub relay_server: &'static str,
    pub custom_rendezvous_server: &'static str,
}

/// Configuration injected at build time
const BUILD_CONFIG: BuildConfig = BuildConfig {
    key: "your-key-here",
    api_server: "https://api.your-server.com",
    relay_server: "https://relay.your-server.com",
    custom_rendezvous_server: "your-server.com",
};

/// Apply the build-time configuration
pub fn apply_build_config() {
    let config = &BUILD_CONFIG;

    if !config.key.is_empty() {
        Config::set_option("key".to_string(), config.key.to_string());
        log::info!("Applied build-time client key");
    }
    // ... applies other settings
}
```

## GitHub Actions Example

```yaml
name: Build Custom RustDesk

on:
  workflow_dispatch:
    inputs:
      rendezvous_server:
        description: 'Rendezvous server hostname'
        required: true
        type: string
      client_key:
        description: 'Client authentication key'
        required: true
        type: string

jobs:
  build:
    runs-on: ubuntu-latest
    env:
      CUSTOM_CLIENT_KEY: ${{ github.event.inputs.client_key }}
      CUSTOM_RENDEZVOUS_SERVER: ${{ github.event.inputs.rendezvous_server }}

    steps:
      - uses: actions/checkout@v4
      - uses: dtolnay/rust-toolchain@stable

      - name: Build
        run: cargo build --release --features flutter

      - name: Upload Artifact
        uses: actions/upload-artifact@v4
        with:
          name: rustdesk-custom-${{ github.event.inputs.rendezvous_server }}
          path: target/release/rustdesk*
```

## Security Considerations

1. **Client Keys**: Treat as secrets - use GitHub Secrets or environment variables
2. **Binary Distribution**: Custom clients have embedded keys - distribute carefully
3. **Version Control**: Never commit `src/custom_config.rs` to git
4. **Build Logs**: Ensure CI logs don't expose sensitive values

## Troubleshooting

### Build fails with "custom_config not found"

**Solution**: Ensure `generate_custom_config()` runs before compilation. The build.rs should handle this automatically.

### Configuration not applied

**Check**:
1. Environment variables are set during build
2. `apply_build_config()` is called early enough
3. Check logs for "Applied build-time..." messages

### String escaping issues

**Solution**: The build scripts handle escaping automatically. If using custom values with special characters, use the Python script or ensure proper escaping in build.rs.

## Advanced Usage

### Conditional Configuration

You can check if custom config is available:

```rust
if crate::custom_config::has_custom_config() {
    println!("Running with custom configuration");
    let (key, api, relay, rendezvous) = crate::custom_config::get_effective_config();
    // Use the configuration
}
```

### Override at Runtime

Build-time config can be overridden by runtime config changes through the normal settings interface.

### Multiple Builds

For different environments, use different environment variable sets:

```bash
# Production build
export CUSTOM_RENDEZVOUS_SERVER="prod.example.com"
export CUSTOM_CLIENT_KEY="prod-key"
cargo build --release

# Staging build
export CUSTOM_RENDEZVOUS_SERVER="staging.example.com"
export CUSTOM_CLIENT_KEY="staging-key"
cargo build --release --target-dir target/staging
```

## Migration from Legacy Custom Clients

If you were using the legacy `custom.txt` file system:

1. The new system is **build-time** instead of **runtime**
2. Configuration is **embedded in binary** instead of external file
3. No need to distribute separate config files
4. Better for CI/CD integration

The legacy `load_custom_client()` function is still available and works alongside the new system.
